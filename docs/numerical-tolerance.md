# 数值验收

OpenCV CPU 决定语义和精度。Python 参考使用 `reference/OP.py` 中的 `cv2`
实现，C++ 验收调用 `cv::Mat` 版本。六个已有 Python profile 的原 Torch 参考
用独立测试与 OpenCV CPU 交叉验证。OpenCV CUDA 用于同设备性能对照。

| 规则 | 当前用例 |
| --- | --- |
| 整数输出逐位一致 | 8U/16U add、subtract、multiply。新增整数和插值模式也从逐位一致开始。 |
| 存储位模式逐位一致 | bitwise_and、bitwise_not、flip，包含浮点存储的符号位与 NaN 载荷。 |
| 逐元素浮点误差 | 算术 32F 使用 `atol=0, rtol=1e-5`，16F 使用 `atol=0, rtol=1e-4`。要求满足 `abs(actual - expected) ≤ atol + rtol * abs(expected)`。同号无穷和同位置 NaN 单独比较。 |
| 可审查例外 | ±1 LSB 仅用于有可复现舍入差异的指定算子、参数和输入域。当前六个算子没有 LSB 例外。 |
| 结构化输出 | 由算子定义比较方法。提交输出结构、匹配规则与空输出、并列、顺序等边界用例。 |

Python 与 C++ 浮点阈值来自 `helpers/tolerance.json`。掩码外像素、ROI 外字节和
只读输入都执行独立的逐字节比较。

## 16U 乘法

C++ 参考关闭 OpenCV CPU 优化分派。在固定的 x86 OpenCV 5.0.0 构建上，
关闭优化后，两个操作数都为 65535 时，`1×1 U16C1` 仍返回 0，`1×8 U16C1`
返回 65535。启用优化时，本次对照的两个尺寸都返回 0。

**正式参考例外只适用于单位缩放的 `1×1 U16C1` 逐元素乘法。** 先将两个
操作数转为无符号 32 位整数，再取 `min(a * b, 65535)`，要求输出逐位一致。
其余已验证尺寸仍与关闭优化的 OpenCV CPU 比较。此处没有容差放宽。
确定性回归同时覆盖 `1×1` 最大值乘法和 `1×8` 饱和边界、零及普通乘积。
该回归不代表穷举了全部输入组合。

OpenCV CUDA 的大乘积也观察到差异，因此同设备性能对照仍将两个操作数
限定在 `[0, 32767]`，并在计时前验证正确性。性能输出用
`input_domain=u16_product_in_i32` 标记这一范围。


## 仿射采样

`warpAffine` 使用 OpenCV 5.0.0 的固定 SSE3、无动态 CPU 指令集分派、无 IPP
构建作为参考。矩阵和每行坐标采用分离的 FP32 乘加。固定探针对 8U、16U 和
32F 的 C1/C3/C4 验证该配置。NEAREST、LINEAR 与 AREA 把参考输出宽度增加至少
128，再上取整为 128 的倍数并裁切，以选定 SIMD 路径。自然宽的标量行尾在
坐标 tie 处可能取到另一源像素。CUBIC 按自然宽参考。CUBIC + REFLECT_101
有单像素源轴时，固定 CPU 构建的边框助手会循环，专项参考先复制该轴一次，
使反射 taps 读取同一像素。常量边框保留固定 CUBIC 路径在左侧和上侧的
加权累加，包括窗口起点为 -4 的位置。CUBIC 常量边框按固定 CPU 的
四像素 SIMD 组判断是否整组填入常量，保留行尾重叠组与短块零坐标填充。

整数输出要求逐位一致。32F 逐元素误差上限为
`min(1e-4, 5e-5 * max(1, abs(reference)))`。透明边框先给两侧目标填入相同像素。
目标外围和源图全部字节独立验证。
