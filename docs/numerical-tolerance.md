# 数值验收

OpenCV CPU 决定语义和精度。Python 参考使用 `reference/OP.py` 中的 `cv2`
实现，C++ 验收调用 `cv::Mat` 版本。六个已有 Python profile 的原 Torch 参考
用单独的测试对照 OpenCV CPU 输出。OpenCV CUDA 用于同设备性能对照。

| 规则 | 当前用例 |
| --- | --- |
| 整数输出逐位一致 | 8U/16U add、subtract、multiply。新增整数和插值模式也从逐位一致开始。 |
| 存储位模式逐位一致 | bitwise_and、bitwise_not、flip，包含浮点存储的符号位与 NaN 载荷。 |
| 逐元素浮点误差 | 算术 32F 使用 `atol=0, rtol=1e-5`，16F 使用 `atol=0, rtol=1e-4`。要求满足 `abs(actual - expected) ≤ atol + rtol * abs(expected)`。同号无穷和同位置 NaN 单独比较。 |
| 可审查例外 | ±1 LSB 仅用于有可复现舍入差异的指定算子、参数和输入域。当前六个算子没有 LSB 例外。 |
| 结构化输出 | 由算子定义比较方法。提交输出结构、匹配规则与空输出、并列、顺序等边界用例。 |

Python 与 C++ 浮点阈值来自 `helpers/tolerance.json`。掩码外像素、ROI 外字节和
只读输入都执行独立的逐字节比较。

## 16U 乘法

C++ 参考关闭 OpenCV CPU 优化分派。在固定的 x86 OpenCV 5.0.0 构建上，
关闭优化后，两个操作数都为 65535 时，`1×1 U16C1` 仍返回 0，`1×8 U16C1`
返回 65535。启用优化时，本次对照的两个尺寸都返回 0。

**正式参考例外只适用于单位缩放的 `1×1 U16C1` 逐元素乘法。** 先将两个
操作数转为无符号 32 位整数，再取 `min(a * b, 65535)`，要求输出逐位一致。
其余已验证尺寸仍与关闭优化的 OpenCV CPU 比较。此处没有容差放宽。
确定性回归同时覆盖 `1×1` 最大值乘法和 `1×8` 饱和边界、零及普通乘积。
该回归不代表穷举了全部输入组合。

OpenCV CUDA 的大乘积也观察到差异，因此同设备性能对照仍将两个操作数
限定在 `[0, 32767]`，并在计时前验证正确性。性能输出用
`input_domain=u16_product_in_i32` 标记这一范围。


## 仿射采样

`warpAffine` 使用 OpenCV 5.0.0 的固定 SSE3、无动态 CPU 指令集分派、无 IPP
构建作为参考。矩阵和每行坐标采用分离的 FP32 乘加。固定用例对 8U、16U 和
32F 的 C1/C3/C4 验证该配置。NEAREST、LINEAR 与 AREA 把参考输出宽度增加至少
128，再上取整为 128 的倍数并裁切，以选定 SIMD 路径。自然宽的标量行尾在
坐标 tie 处可能取到另一源像素。CUBIC 按自然宽参考。CUBIC + REFLECT_101
有单像素源轴时，固定 CPU 构建的边框助手会循环，专项参考先复制该轴一次，
使反射 taps 读取同一像素。常量边框保留固定 CUBIC 路径在左侧和上侧的
加权累加，包括窗口起点为 -4 的位置。CUBIC 常量边框按固定 CPU 的
四像素 SIMD 组判断是否整组填入常量，保留行尾重叠组与短块零坐标填充。

8U 和 16U 的常量边框按固定 SSE3 参考先舍入到最近的有符号 32 位整数，
中点取偶数，再饱和到像素范围。有限值超出该整数转换范围时，固定构建产生
`INT_MIN`，饱和结果为零。该行为通过四种插值和多通道常量回归固定。

整数输出要求逐位一致。32F 逐元素误差上限为
`min(1e-4, 5e-5 * max(1, abs(reference)))`。透明边框先给两侧目标填入相同像素。
目标外围和源图全部字节分别验证。


## Resize

正确性采用 contrib `2f5682ba` 的通用 CPU 参考，指定 128 位 SIMD
和标量行尾的运算顺序。8U 输出与 NEAREST 搬运逐位比较。
对输入绝对值不超过 2 的有限 32F，用逐元素绝对误差上限验证
LINEAR（4.948e-7）、CUBIC（1.401e-6）、AREA（8.419e-7）。
这里的输入绝对值是误差测量包络，接口仍接受 32F 的完整像素范围。
同尺寸进入 copy 分派。独立回归让固定 OpenCV 的 `cv::resize` 直接
解析尺寸和计算输出，覆盖 6→34 最近邻、CUBIC 中点和行尾、分数 AREA、
混合放缩、非整数 fx/fy 和 LINEAR 2 倍下采样的 AREA 别名。

大整数窗口的 AREA 以 contrib 的宽累加 CPU 参考为正式合同。
全 255 的 4096×2160 缩到一个像素时，精确和为 2,256,076,800，
正式输出为 255。固定 OpenCV 此例返回 0，单列为原生 CPU 累加范围差异。


## cvtColor

全部 124 个 code-depth 组合逐例调用固定 OpenCV CPU `cv::cvtColor`，
由 CPU 直接生成尺寸、通道及输出。整数和 32F 通道复制按位比较，
复制用例含 NaN 载荷、无穷和负零。32F 算术采用固定 SSE3 四像素分离乘加
配置，每个像素的误差上限为 `8 * 2^-24 * max(1, |ref|, max(|src channels|))`。
定向有限输入还验证了 1e-4 绝对上限。输入范围从单位幅度覆盖到 ±131070，
该验证范围用于表述证据，公开接口保留 32F 深度支持。

## 透视与重映射

参考为 OpenCV 5.0.0 固定 SSE3 构建的自然宽 `cv::warpPerspective` 和
`cv::remap`，使用 `ALGO_HINT_ACCURATE`。整数逐位一致。32F 的逐元素误差上限为
`min(1e-4, 5e-5 * max(1, abs(reference)))`，同位置 NaN 和同号无穷独立匹配。
透视的 NEAREST／LINEAR 使用窄化的 FP32 系数、分离乘加及除法，保留自然行尾的
求值顺序。分母零和在 FP32 窄化后成为零的分母按该路径的坐标与边界规则采样。
CUBIC 使用 FP32 行项、FP64 投影以及窄化的采样坐标。浮点 remap 的 NEAREST
与 LINEAR 使用完整浮点坐标，定点 remap 从整数图及 5+5 位索引构造权重。
透明 LINEAR 的浮点路径用原目标像素填缺失 taps，定点路径保留无源基点并对边缘
有效 taps 重归一。透明 CUBIC 的边缘助手对组内缺失 taps 使用该四像素组的首个
原目标值，整组跳过时保留原目标内容。ROI 外和只读输入均按字节验证。

## filter2D 半权专项参考

固定 OpenCV `40738fb` 使用 SSE3、单线程、无额外 SIMD 分派及 IPP。
以下四个专项配置使用数学结果作为正式参考，输出仍须逐位一致。

| 输入与输出深度 | 通道 | 方核 |
| --- | --- | --- |
| 8U → 8U | C1 | 13×13、17×17 |
| 16U → 16U | C1 | 9×9、11×11 |

四例均为 19 行 × 37 列独立视图，核为 CV_64F，中心锚点且唯一非零
系数为中心的 `0.5`。使用 `REFLECT_101`，CPU 参考加 `BORDER_ISOLATED`，
`delta` 为零。每个输入像素 `p` 的期望值为 `q + ((p & 1) & (q & 1))`，
其中 `q = p / 2` 取整数商。奇数在半步取偶数，偶数准确除以二。

固定 CPU 的离散傅里叶变换（DFT）相关在半步两侧产生舍入差异。
原奇数图每例 703 像素，8U 两例各差 173、230 处，16U 两例各差 290、331 处。
同为输入 `1` 的不同坐标可得到 `0` 和 `1`。诊断保留固定 CPU 的有符号差，
`--filter2d-half-reference` 对奇偶输入执行公开 C++ 的逐位检查。

8U 的 11×11、16U 的 7×7，以及非零 `delta` 的控制仍采用固定 CPU。
较大核的非半步相消、其它深度和布局继续按原参考单独验证。
